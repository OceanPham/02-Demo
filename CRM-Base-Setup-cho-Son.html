01Hai luật bất biến

1

Chỉ làm việc và commit trên son-dev

Mọi thay đổi của anh Sơn phải được commit trên son-dev. Trước khi sửa code, commit hoặc push, kiểm tra nhánh. Không commit lên main, không tự tạo nhánh khác và không tự merge vào nhánh chung.

2

Local dùng dữ liệu production: chỉ được xem

Chạy trên máy anh Sơn vẫn kết nối dữ liệu thật của công ty. Không thêm, không sửa, không xóa dữ liệu bằng giao diện, API, script hay AI. Nhánh riêng và địa chỉ localhost không tạo ra database riêng.

Không bấm Save, Create, Add, Delete, Send, Confirm, đổi trạng thái, kéo thả để cập nhật, ghi payment hoặc chỉnh hóa đơn. Không chạy seed, import, migration, upload file, đồng bộ mail hay script thử ghi vào Base44. Quy tắc áp dụng với mọi bản ghi, kể cả draft-0044.

Được sửa mã nguồn theo task. Nếu cần kiểm thử thao tác ghi, phải dùng mock / fixture hoặc backend thử nghiệm cách ly hoàn toàn với production. Chưa có môi trường đó thì chỉ kiểm tra phần đọc và báo phần chưa kiểm thử.

Đây là quy tắc vận hành, không phải một khóa kỹ thuật đã tự bật. Giao diện có thể vẫn cho phép bấm nút ghi. Anh Sơn và AI phải chủ động tuân thủ.

02Chuẩn bị trước khi cài

  1. VS Code đã có sẵn. Mở VS Code, chọn Terminal → New Terminal. Trong menu cạnh nút + của Terminal, chọn Select Default Profile → PowerShell, rồi mở terminal mới.
  2. Tài khoản GitHub có quyền repo. Đăng nhập GitHub và mở repository HaiRetail/CRM-Base. Nếu thấy 404 hoặc không xem được code, nhờ người phụ trách cấp quyền; nếu có lời mời collaborator thì nhận lời mời trước.
  3. Nhận cấu hình local và quyền đăng nhập app. Nhờ người phụ trách gửi riêng hai giá trị VITE_BASE44_APP_ID, VITE_BASE44_APP_BASE_URL và cấp tài khoản ứng dụng phù hợp. Không đưa mật khẩu, access token hoặc file cấu hình vào Git.
  4. Chọn chỗ lưu code. Tài liệu dùng thư mục C:\Users\<ten-Windows>\source\CRM-Base. Không cần ổ E: giống máy người khác. Tránh thư mục đang đồng bộ OneDrive để giảm lỗi khóa file.

Cách dùng lệnh: chạy từng khối, chờ xong và đọc kết quả rồi mới sang khối tiếp. Các lệnh bên dưới dành cho anh Sơn nhập trực tiếp trong PowerShell; không gõ thêm ký hiệu PS C:\... ở đầu dòng. Nếu có chỗ ghi “thay giá trị”, phải thay trước khi chạy.

Khi AI thực thi terminal trong repository, AI còn phải tuân thủ quy tắc rtk của AGENTS.md; xem bước 10.

03Kiểm tra và cài Git

3.1. Kiểm tra Git đã có chưa

PowerShell · kiểm tra
git --version

Nếu hiện git version 2.x.x... thì đã có Git, chuyển đến bước 4. Nếu báo git is not recognized hoặc The term 'git' is not recognized, cài theo mục tiếp.

3.2. Nếu chưa có Git

  1. Mở Git for Windows, tải bản Setup phù hợp máy: thường là x64; dùng ARM64 nếu máy chạy Windows ARM.
  2. Chạy bộ cài. Giữ các lựa chọn mặc định; ở phần PATH chọn Git from the command line and also from 3rd-party software. Giữ Git Credential Manager để đăng nhập GitHub qua trình duyệt.
  3. Cài xong, đóng toàn bộ cửa sổ VS Code, mở lại và chọn Terminal → New Terminal.
  4. Chạy lại git --version. Chỉ sang bước tiếp khi đã thấy phiên bản.

Nguồn tải: trang cài đặt chính thức của Git.

04Kiểm tra Node.js phải ≥ 20

4.1. Xem phiên bản Node.js và npm

PowerShell · chạy từng dòng
node -v
npm -v

Ví dụ v22.23.2 nghĩa là Node.js major version 22, đáp ứng yêu cầu ≥ 20. v18.x.x hoặc v16.x.x không đạt.

Node ≥ 20, npm chạyĐã đạt ngưỡng yêu cầu. Có thể sang bước 6; không bắt buộc cài NVM nếu Node hiện tại dùng ổn.
Node dưới 20Sang bước 5: kiểm tra NVM, cài / chọn bản Node mới hơn.
Không tìm thấy nodeSang bước 5. Đây là tình huống bình thường trên máy chưa cài Node.
npm.ps1 bị chặnThử npm.cmd -v. Nếu chạy được thì Node đã có; xem cách dùng npm.cmd ở bước 12.

4.2. Kiểm tra ngưỡng bằng lệnh

Chỉ chạy khi node -v đã trả về phiên bản:

PowerShell · xác nhận Node ≥ 20
node -e "const major=Number(process.versions.node.split('.')[0]); if(major<20){console.error('CAN NANG CAP: Node.js >= 20');process.exit(1)} console.log('OK: Node.js '+process.versions.node)"
Đạt: hiện OK: Node.js .... Nếu hiện CAN NANG CAP, thực hiện bước 5.

Khuyến nghị cho máy cài mới: Node.js 22 LTS. Ngưỡng “≥ 20” là yêu cầu tối thiểu; Node 20 đã hết vòng hỗ trợ tại ngày cập nhật tài liệu. Chọn nhánh LTS còn được hỗ trợ; nếu gặp EBADENGINE thì dùng Node 22 bản vá mới nhất hoặc phiên bản được team thống nhất.

Tình trạng hỗ trợ phiên bản: Node.js Releases.

05Chưa có Node phù hợp: dùng NVM

NVM for Windows giúp cài và chuyển giữa nhiều phiên bản Node.js. Đây là bản cho Windows; không dùng lệnh cài NVM dành cho macOS / Linux trong PowerShell.

5.1. Kiểm tra đã có NVM chưa

PowerShell · tìm NVM
where.exe nvm
nvm

Nếu dòng đầu hiện đường dẫn nvm.exe và dòng sau hiện thông tin / danh sách lệnh NVM: đã cài, chuyển đến 5.3. Nếu không tìm thấy NVM, thực hiện 5.2. Nếu vừa cài mà vẫn không thấy, đóng VS Code và mở lại trước khi cài thêm.

5.2. Cài NVM for Windows

  1. Mở nvm-windows.com, chọn tải Community Build cho Windows.
  2. Chọn installer x64 cho máy Intel / AMD; chọn ARM64 nếu Settings → System → About → System type ghi ARM. Tải file Setup .exe, không tải source code.
  3. Với bản v2, mở installer bằng tài khoản Windows đang dùng; không chủ động chọn Run as administrator. Chọn Next qua wizard, chấp nhận điều khoản nếu đồng ý; giữ cấu hình mặc định / shim.
  4. Nếu phát hiện Node cài riêng, đọc lựa chọn Adopt: chuyển Node hiện có sang NVM và gỡ bản cài riêng. Không chọn xóa nếu chưa hiểu tác động.
  5. Chọn Install, đợi xong rồi Finish nếu wizard có các nút này. Đóng VS Code / terminal, mở lại và kiểm tra theo 5.1.

Cách cài và xử lý Node hiện có: NVM Windows — Installers. Giao diện installer có thể thay đổi theo phiên bản.

Nếu máy đã dùng NVM v1 từ trước

Không bắt buộc nâng NVM chỉ để setup project nếu cài và chọn Node vẫn hoạt động. Bản v1 thường dùng installer tên nvm-setup.exe và có thể cần quyền Administrator khi nvm use tạo symlink. Chỉ mở PowerShell bằng Run as administrator để xử lý lỗi quyền của v1 nếu cần; VS Code chạy project vẫn mở bình thường.

Không cài chồng hai hệ NVM. Nếu v1 không nhận phiên bản rút gọn 22, dùng đúng số đầy đủ mà nvm list hiển thị.

Tham khảo: NVM Windows — Common Issues.

5.3. Cài và kích hoạt Node.js 22

Chạy lần lượt. Chờ nvm install 22 cài xong thành công rồi mới chạy nvm use 22.

PowerShell · cài Node và chuyển phiên bản
nvm install 22
nvm use 22
nvm list
node -v
npm -v

install tải Node; use chọn bản đang chạy. Chỉ cài xong mà chưa chọn thì node -v có thể vẫn hiện bản cũ. nvm list liệt kê các bản đã cài.

Kết quả cần thấy: node -v trả về v22.x.x, npm -v trả về một số phiên bản. Số patch có thể khác ví dụ trong tài liệu.

Nếu NVM yêu cầu số đầy đủ, nhìn kết quả nvm list rồi chạy nvm use kèm số đó, ví dụ nvm use 22.23.2 chỉ khi bản này đã có trong danh sách trên máy anh.

Chạy lại lệnh kiểm tra ngưỡng ở 4.2. Nếu terminal mới chưa nhận phiên bản, đóng VS Code, mở lại và kiểm tra lại.

Cú pháp: nvm install, nvm use, nvm list.

06Clone repository và chuyển son-dev

6.1. Tạo thư mục chứa project

PowerShell · tạo thư mục source trong tài khoản Windows
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\source"
Set-Location "$env:USERPROFILE\source"

6.2. Clone code về máy

PowerShell · clone đúng repository
git clone https://github.com/HaiRetail/CRM-Base.git

Nếu Git mở trình duyệt để xác thực, đăng nhập đúng tài khoản GitHub đã được cấp quyền và hoàn tất xác thực. Không dùng mật khẩu GitHub làm mật khẩu Git qua terminal. Nếu Git yêu cầu token mà anh chưa có, dùng luồng đăng nhập của Git Credential Manager hoặc nhờ người phụ trách hỗ trợ; không dán token vào URL clone.

PowerShell · vào project sau khi clone thành công
Set-Location CRM-Base
git remote -v
git fetch origin
git branch -r
Kiểm tra: remote origin trỏ đến https://github.com/HaiRetail/CRM-Base.git, danh sách nhánh có origin/son-dev.

6.3. Chuyển sang nhánh đã tạo cho Sơn

Với lần clone mới, chạy:

PowerShell · tạo nhánh local theo đúng remote son-dev
git switch --track origin/son-dev

Nếu báo nhánh son-dev đã tồn tại trên máy, chỉ cần:

PowerShell · chỉ dùng khi son-dev local đã tồn tại
git switch son-dev
PowerShell · bắt buộc kiểm tra sau khi chuyển
git branch --show-current
git status -sb
Dòng đầu phải đúng son-dev. Lần clone mới, status thường bắt đầu bằng ## son-dev...origin/son-dev.

Nếu vẫn hiện main, nhánh khác hoặc không có origin/son-dev: dừng trước khi sửa code. Kiểm tra lỗi của lệnh chuyển nhánh và nhờ người phụ trách xác nhận. Không tự tạo son-dev từ main để bỏ qua lỗi.

6.4. Mở đúng thư mục trong VS Code

PowerShell · mở thư mục hiện tại
code .

Nếu không có lệnh code, chọn File → Open Folder..., chọn thư mục CRM-Base vừa clone. Khi được hỏi Workspace Trust, chỉ chọn tin cậy sau khi đã kiểm tra đúng repo của team.

Mở Terminal → New Terminal trong cửa sổ project. Explorer phải thấy package.json, package-lock.json, src/, base44/ và AGENTS.md. Góc trái thanh trạng thái VS Code phải là son-dev.

6.5. Khai báo tên và email người commit

Thay EMAIL_GITHUB_CUA_ANH bằng email commit của tài khoản GitHub (có thể là email noreply do GitHub cung cấp). Chạy trong CRM-Base; cấu hình này chỉ áp dụng cho repo này.

PowerShell · thay email trước khi chạy
git config user.name "Son"
git config user.email "EMAIL_GITHUB_CUA_ANH"
git config --get user.name
git config --get user.email

Tên và email dùng để ghi tác giả commit; chúng không thay cho bước đăng nhập hoặc cấp quyền GitHub.

Tham khảo clone HTTPS và quyền truy cập: GitHub — Cloning a repository.

07Tạo .env.local đúng cấu hình

Không thể chỉ clone rồi chạy là đủ. App cần cấu hình Base44. File .env.local bị Git bỏ qua nên thường không có trong bản clone.

  1. Trong Explorer của VS Code, chọn thư mục gốc CRM-Base, bấm New File..., đặt đúng tên .env.local.
  2. File phải nằm cùng cấp với package.json, không nằm trong src/, không có đuôi .txt.
  3. Dán mẫu bên dưới, thay hai phần DIEN_... bằng giá trị thật do người phụ trách gửi riêng. Nếu nhận nguyên file từ team, dùng file đó thay vì tự đoán.
  4. Lưu bằng Ctrl + S. Sau mỗi lần đổi env, dừng dev server bằng Ctrl + C và chạy lại.
Nội dung file .env.local · không chạy trong terminal
VITE_BASE44_APP_ID=DIEN_APP_ID_DO_TEAM_CUNG_CAP
VITE_BASE44_APP_BASE_URL=DIEN_BACKEND_URL_DO_TEAM_CUNG_CAP
PORT=5178

Mẫu trên chưa phải cấu hình dùng được. Không giữ nguyên placeholder. Không lấy App ID / URL ví dụ trong README, không tự suy ra backend URL và không đưa access token vào file HTML này.

Không tự thêm NODE_ENV=development theo hướng dẫn cũ để mở luồng sửa deadline. Thiết lập local không cho phép anh Sơn ghi dữ liệu thật.

Xác nhận Git đang bỏ qua file:

PowerShell · kiểm tra ignore, không hiển thị nội dung env
git check-ignore .env.local
Cần thấy .env.local. Nếu không có kết quả, nhờ người phụ trách kiểm tra trước khi stage / commit. Không dùng git add -f với file cấu hình.

Frontend chạy bằng Vite + React; backend và dữ liệu vẫn trên Base44. Bước này không tạo database local, không cần chạy seed và không cần cài database để setup frontend.

08Cài project và chạy cổng 5178

8.1. Kiểm tra trước khi cài

PowerShell · tại thư mục CRM-Base
Get-Location
git branch --show-current
node -v
npm -v
Test-Path package.json
Test-Path package-lock.json
Test-Path .env.local

Đường dẫn phải kết thúc bằng CRM-Base, nhánh là son-dev, Node đạt yêu cầu, ba lệnh Test-Path đều trả về True. Nếu thiếu file, quay lại bước tương ứng trước khi cài.

8.2. Cài thư viện của project

PowerShell · cài theo package-lock.json
npm ci

Repo có package-lock.json, nên dùng npm ci để cài đúng các phiên bản đã khóa. Chờ lệnh kết thúc và terminal nhận lệnh mới. Lần đầu có thể mất vài phút tùy mạng; thư viện được cài vào node_modules/.

Lệnh cài thông thường là npm install, nhưng có thể làm thay đổi lockfile. Với project này, ưu tiên npm ci. Nếu lỗi lockfile, không tự xóa package-lock.json hoặc đổi thư viện để “cài cho qua”; gửi nguyên lỗi cho người phụ trách.

Cài đặt theo lockfile: npm — npm ci.

Cảnh báo package deprecated / vulnerabilities không đồng nghĩa đã cài thất bại. Kiểm tra có npm error hay không. Không tự chạy npm audit fix --force vì có thể đổi phiên bản ngoài phạm vi task.

8.3. Khởi động local

PowerShell · chạy đúng cổng, không tự nhảy cổng khác
npm run dev -- --port 5178 --strictPort

npm run dev gọi Vite; -- chuyển các tham số phía sau cho Vite; --port 5178 chọn cổng; --strictPort báo lỗi nếu cổng bận thay vì chuyển sang cổng khác.

Khi server chạy, terminal tiếp tục mở và không trả lại dấu nhắc nhập lệnh. Repo đặt mức log là error, nên có thể không có banner “ready” như các project Vite khác.

8.4. Mở ứng dụng

Mở Edge / Chrome và nhập địa chỉ local theo yêu cầu:

Địa chỉ mở trong trình duyệt · không phải lệnh terminal
http://localhost:5178/

Giữ terminal chạy suốt lúc dùng app. Nếu cần chạy lệnh Git, mở terminal thứ hai bằng nút +. Sửa và lưu mã nguồn thường được Vite cập nhật tự động trên trình duyệt.

8.5. Dừng / chạy lại

Chọn terminal đang chạy Vite, nhấn Ctrl + C; nếu được hỏi xác nhận dừng thì xác nhận. Lần sau chạy lại bằng đúng lệnh ở 8.3. Không cần cài lại thư viện mỗi lần mở máy; chỉ cài lại khi dependencies thay đổi hoặc môi trường cần khôi phục.

09Kiểm tra kết quả theo chế độ chỉ xem

  1. App mở được trên cổng 5178, không có lỗi thiếu cấu hình Base44.
  2. Nếu được yêu cầu đăng nhập, dùng tài khoản app được team cấp. GitHub và tài khoản app có thể khác nhau. Nếu chưa được cấp quyền, báo người phụ trách; không tự đăng ký để tạo dữ liệu thử hoặc tắt kiểm tra quyền trong code.
  3. Khi có lựa chọn ngôn ngữ, dùng English để trao đổi tên màn hình / nút với team thống nhất.
  4. Chỉ mở các màn hình / chi tiết đã biết là chỉ đọc. Có thể xem bố cục, đọc số liệu và dùng bộ lọc không lưu vào hệ thống. Không mở tính năng tự đồng bộ, tự khởi động timer hoặc tự cập nhật dữ liệu khi tải.
  5. Không thử chức năng bằng cách sửa một bản ghi thật rồi “đổi lại như cũ”. Ghi rồi hoàn tác vẫn là ghi production.

Nếu cần kiểm thử Create / Save / Delete: dùng dữ liệu mẫu với client mock hoặc backend riêng đã được xác nhận cách ly. Dữ liệu mẫu nằm trong database production vẫn là production. Không chỉ đổi tên project / task để coi đó là môi trường an toàn.

Checklist setup chỉ xác nhận máy chạy được frontend và phần xem được cấp quyền. Nó không xác nhận các luồng ghi đã được kiểm thử.

10Thiết lập cách làm việc với AI

10.1. Cho AI đúng ngữ cảnh

  1. Mở workspace gốc CRM-Base trong VS Code. Nếu dùng extension AI của team, cài qua Extensions (Ctrl + Shift + X) và đăng nhập tài khoản cá nhân được phép sử dụng.
  2. Yêu cầu AI đọc AGENTS.md ở gốc repository trước khi sửa. Không mặc định mọi công cụ AI đều tự đọc file này.
  3. Dán nguyên khối quy tắc ở 10.2 vào đầu mỗi cuộc chat / phiên AI mới, sau đó mô tả task cụ thể. Nếu công cụ có project instructions, có thể lưu thêm ở đó; không sửa / ghi đè luật repo để nới quyền.
  4. AI phải kiểm tra nhánh và cả working tree / staging area, nêu đúng phạm vi file định sửa rồi làm task. Nếu có thay đổi chưa rõ nguồn gốc, giữ nguyên và không gom vào commit.

10.2. Sao chép và dán nguyên khối này cho AI

Prompt bắt buộc · dán vào chat AI, không chạy terminal
Bạn đang hỗ trợ Sơn phát triển WorkFlow / CRM-Base trên Windows.
Hãy đọc AGENTS.md ở gốc repo trước khi làm việc và tuân thủ toàn bộ hướng dẫn liên quan.

HAI LUẬT BẤT BIẾN:
1. Nhánh làm việc duy nhất của Sơn là son-dev. Trước khi sửa code, commit hoặc push, kiểm tra git branch --show-current. Chỉ tiếp tục khi đúng son-dev. Không commit lên main hoặc nhánh khác; không tự tạo nhánh / worktree khác; không tự merge vào nhánh chung. Nếu sai nhánh hoặc chuyển nhánh bị lỗi, dừng phần chỉnh sửa và báo Sơn.
2. Local kết nối cùng dữ liệu production trên Base44. Chỉ được xem dữ liệu. Tuyệt đối không thêm, sửa, xóa bằng UI, API, script hoặc automation; không seed / import / migration / upload; không Save, Send, đổi trạng thái, payment, chỉnh hóa đơn hay kéo thả để lưu. Không có ngoại lệ cho draft-0044. Không thử ghi rồi hoàn tác. Kiểm tra cả tác dụng phụ khi mở màn hình / chạy effect. Luồng cần ghi phải dùng mock / fixture hoặc backend cách ly hoàn toàn, không kết nối production; nếu chưa có thì báo chưa kiểm thử phần ghi.

CÁCH THỰC HIỆN:
3. Trước khi sửa, đọc yêu cầu và tài liệu liên quan; kiểm tra git status, git diff và git diff --cached. Giữ nguyên các thay đổi không thuộc task. Phân biệt sửa UI, logic, schema và thao tác dữ liệu.
4. Chỉ sửa code đúng phạm vi task. Không tự gọi hàm backend có tác dụng ghi; không tự deploy backend, Publish, gửi mail / tin nhắn hoặc thực hiện thao tác bên ngoài repo. Không tắt auth / phân quyền hoặc tạo cờ giả để coi production là sandbox.
5. Khi sửa logic dữ liệu, đọc schema trong base44/entities/ trước. Dùng Base44 client chung ở src/api/base44Client.js và helper sẵn có. Giữ frontend JavaScript; không tự thêm REST layer hoặc Redux.
6. Khi sửa UI, theo docs/ui-standards/HANDBOOK.md và src/components/standards/. Không sửa component sinh tự động trong src/components/ui/. Dùng useRole, useI18n; thêm chuỗi mới ở đủ nl/en/vi. Nếu có form, đọc skill form-controls.
7. Khi AI chạy terminal, dùng prefix rtk theo AGENTS.md. Nếu chưa có RTK, báo rõ công cụ chưa khả dụng, không tự xóa / sửa luật repo. Các lệnh gốc trong guide là để Sơn thiết lập máy thủ công.
8. Chạy kiểm tra phù hợp trong các script có thật của package.json. Không tự đặt ra npm test. Với lint / typecheck, phân biệt lỗi nền và lỗi mới. Xác minh UI chỉ đọc; phần cần ghi dùng môi trường mẫu cách ly. Không tạo đầu ra trong reports/; ảnh / log tạm lưu ngoài repo.
9. Chỉ commit khi Sơn yêu cầu; luôn commit trên son-dev và chỉ gồm thay đổi thuộc task hiện tại. Kiểm tra cả staging area; stage từng file / từng hunk cần thiết. Không git add . hoặc git add -A. Không commit .env.local, token, mật khẩu, node_modules hay dist.
10. Chỉ push khi Sơn yêu cầu và chỉ push origin son-dev. Không force push, reset --hard, clean hoặc tự rebase để giải quyết lỗi. Không tự merge PR hoặc Publish. Nếu lệnh bị từ chối / có conflict, báo nguyên nhân và giữ dữ liệu hiện tại.
11. Báo đúng điều đã làm: đã code, đã kiểm tra, đã commit, đã push, đã Publish là các trạng thái riêng. Không khẳng định đã kiểm thử phần chưa chạy.

Trước khi bắt đầu task, hãy cho biết: nhánh hiện tại, trạng thái thay đổi đang có và phạm vi bạn sẽ thực hiện. Sau đó làm đúng task tôi giao dưới đây.

“Chỉ xem dữ liệu” không có nghĩa là “không được sửa code”. AI được sửa code theo task, nhưng không được dùng hệ thống dữ liệu thật để thử các thao tác ghi. Anh Sơn vẫn phải xem diff và kiểm soát lệnh AI chuẩn bị chạy.

10.3. Ví dụ giao task rõ ràng

Ví dụ nội dung task sau khối luật
Task: Điều chỉnh khoảng cách hiển thị ở màn hình [tên màn hình].
Yêu cầu: [mô tả hành vi / giao diện cần thay đổi].
Chỉ sửa các file cần thiết cho task này trên son-dev.
Kiểm tra local cổng 5178 theo chế độ chỉ xem; nếu cần test thao tác ghi thì dùng mock cách ly.
Chưa commit, chưa push. Khi xong, báo những gì đã đổi, đã kiểm tra và phần chưa xác minh.

11Quy trình dev, commit và push

11.1. Đầu mỗi phiên làm việc

PowerShell · xem trạng thái trước
git branch --show-current
git status -sb
git diff --stat
git diff --cached --stat

Phải đúng son-dev. Nếu đang nhánh khác và có thay đổi chưa commit, không tự switch / reset / bỏ thay đổi; nhờ người phụ trách xử lý đúng nguồn gốc.

Khi đã đúng nhánh và working tree / staging area sạch, cập nhật từ chính son-dev:

PowerShell · chỉ chạy khi repo sạch và đang son-dev
git pull --ff-only origin son-dev

Nếu bị từ chối vì nhánh phân kỳ / có thay đổi local, dừng và nhờ team xử lý. Không tự kéo main vào, không tự rebase. Nếu package.json / lockfile vừa đổi, chạy lại npm ci; sau đó khởi động local theo 8.3.

11.2. Sửa code và kiểm tra

Đọc AGENTS.md, giao task cho AI theo bước 10, xem diff và xác minh màn hình chỉ đọc. Tùy thay đổi, dùng các lệnh có sẵn:

PowerShell · các lệnh kiểm tra, chạy lần lượt theo phạm vi
npm run lint
npm run typecheck
npm run build

build tạo bản build trong dist/ và chạy bước prebuild khai báo trong package.json; không tự Publish. Không commit thư mục build. Nếu có lỗi nền, báo rõ lỗi nền / lỗi do task; không sửa lan sang tính năng khác chỉ để làm sạch toàn repo.

11.3. Chỉ commit khi task đã sẵn sàng và được yêu cầu

PowerShell · rà soát trước khi stage
git branch --show-current
git status
git diff
git diff --cached

Nhánh phải là son-dev. Kiểm tra cả phần đã stage sẵn; không để file của task khác lọt vào commit.

Mẫu sau cần thay trước khi chạy: thay DUONG_DAN_FILE_THUOC_TASK bằng đường dẫn tương đối thật của file vừa sửa, và thay nội dung message bằng mô tả task. Có nhiều file thì stage từng file. Nếu một file có thay đổi của nhiều task, dùng git add -p để chọn đúng hunk thay vì stage cả file.

PowerShell · mẫu stage một file, phải thay đường dẫn
git add -- "DUONG_DAN_FILE_THUOC_TASK"
git diff --cached --stat
git diff --cached

Chỉ khi phần staged đúng toàn bộ phạm vi task, tạo commit:

PowerShell · chỉ commit nếu đúng son-dev, thay message phù hợp
if ((git branch --show-current) -ceq "son-dev") {
    git commit -m "Fix: mo ta ngan gon thay doi cua task"
    git status -sb
} else {
    throw "DUNG LAI: Nhanh hien tai khong phai son-dev."
}

Không dùng git add ., git add -A hoặc git commit -a để gom thay đổi hàng loạt.

11.4. Push đúng nhánh khi được yêu cầu

PowerShell · chỉ khi đã được yêu cầu push, có kiểm tra son-dev
if ((git branch --show-current) -ceq "son-dev") {
    git push origin son-dev
} else {
    throw "DUNG LAI: Nhanh hien tai khong phai son-dev."
}

Hai khối commit / push trên tự kiểm tra tên nhánh trước khi chạy. Đây chỉ là chốt kiểm tra trong mẫu lệnh, không khóa các cách commit khác của VS Code / AI. Nếu push bị từ chối, xem bước 12; không dùng --force.

Commit, push và Publish là ba việc khác nhau. Commit lưu lịch sử trên máy; push đưa code lên GitHub. Repo có tích hợp Base44, vì vậy phải lưu ý việc đồng bộ Builder theo cấu hình của team; không coi nhánh riêng là một sandbox dữ liệu. Merge vào nhánh chung và Publish do người phụ trách thực hiện theo quy trình, anh Sơn / AI không tự làm.

12Xử lý các lỗi thường gặp

Bấm từng mục để xem. Nếu chưa xử lý được, gửi người phụ trách lệnh vừa chạy + nguyên thông báo lỗi; che thông tin nhạy cảm, không gửi nguyên file env / token.

node / npm / nvm / git is not recognized

Đóng mọi cửa sổ VS Code và terminal, mở lại để nhận PATH mới. Kiểm tra công cụ tương ứng đã cài chưa. Chạy where.exe node, where.exe npm, where.exe nvm, where.exe git để tìm đường dẫn. Nếu có NVM, chạy nvm list, chọn Node đã cài bằng nvm use 22, rồi kiểm tra lại node -v. Không cài chồng nhiều bản Node độc lập để chữa PATH.

npm.ps1 cannot be loaded because running scripts is disabled

Không cần tắt Execution Policy toàn máy. Trong PowerShell dùng bản .cmd tương ứng:

PowerShell · thay cho npm khi npm.ps1 bị chặn
npm.cmd -v
npm.cmd ci
npm.cmd run dev -- --port 5178 --strictPort

Chạy từng lệnh theo đúng giai đoạn setup. Với các lệnh khác, cũng có thể thay npm bằng npm.cmd, ví dụ npm.cmd run build.

NVM cài xong nhưng node -v vẫn ra bản cũ / lỗi quyền

Chạy nvm list và where.exe node. Có thể Node cài riêng đang đứng trước NVM trong PATH. Khởi động lại VS Code trước; nếu vẫn sai, đọc hướng dẫn sửa PATH của NVM hoặc nhờ team hỗ trợ. Với NVM v2 có thể dùng nvm env để xem môi trường. Với v1, lỗi tạo symlink có thể cần PowerShell Administrator khi chọn phiên bản. Không xóa thư mục C:\Program Files\nodejs bằng tay nếu chưa xác định nó là thư mục thật hay link.

Nguồn xử lý lỗi bản mới: NVM — General Troubleshooting.

Repository not found / 403 / Authentication failed

Mở repo trên GitHub bằng đúng tài khoản của anh Sơn. Kiểm tra đã nhận lời mời và có quyền đọc / push. Xác thực lại qua Git Credential Manager nếu đăng nhập nhầm tài khoản. Không tự đổi URL sang repo khác, không đưa token vào URL. Quyền xem repo và quyền push có thể khác nhau.

Clone báo thư mục CRM-Base đã tồn tại

Không xóa thư mục cũ. Kiểm tra có phải bản clone đang dùng không bằng git remote -v trong thư mục đó. Nếu đúng repo, tiếp tục từ bước kiểm tra / chuyển nhánh; nếu thư mục thuộc việc khác, chọn thư mục cha khác để clone. Không clone lồng thêm CRM-Base vào bên trong CRM-Base.

Không thấy origin/son-dev / không switch được

Chạy lại git fetch origin, rồi git branch -r. Nếu không có origin/son-dev, người phụ trách cần kiểm tra nhánh đã được push và quyền truy cập. Nếu branch đã tồn tại local thì dùng git switch son-dev. Nếu có thông báo thay đổi local sẽ bị ghi đè, dừng; không dùng reset / force checkout để vượt lỗi.

npm ci báo ENOENT / không tìm thấy package.json

Terminal đang ở sai thư mục. Chọn thư mục gốc CRM-Base; kiểm tra Get-Location và Test-Path package.json. Không chạy lệnh ở thư mục cha source, cũng không chạy trong src.

npm ci lỗi lockfile / EBADENGINE / tải package thất bại

Với EBADENGINE, kiểm tra node -v và chọn Node 22 bản vá mới nhất / phiên bản team yêu cầu. Với lockfile lệch package.json, gửi lỗi để team sửa đúng nguồn, không xóa lockfile hoặc dùng --force. Nếu lỗi mạng / proxy / certificate, kiểm tra mạng và cấu hình của công ty; không tắt kiểm tra SSL để cài cho qua.

Port 5178 is already in use

Tìm terminal đang chạy project cũ và dừng bằng Ctrl + C nếu đó là phiên của anh. Nếu chưa rõ chương trình nào chiếm cổng, xem tiến trình bằng lệnh chỉ đọc:

PowerShell · xem cổng, không dừng tiến trình
Get-NetTCPConnection -LocalPort 5178 -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess

Nhờ người phụ trách xác định PID trước khi tắt ứng dụng không rõ. Sau khi cổng trống, chạy lại lệnh 8.3. Không bỏ --strictPort để server âm thầm đổi cổng.

localhost không mở / ERR_CONNECTION_REFUSED

Kiểm tra terminal Vite còn chạy, không có lỗi khởi động, và địa chỉ là http://localhost:5178/ (HTTP, không phải HTTPS). Nếu đã đóng terminal, chạy lại lệnh 8.3. Nếu cổng bận, xử lý mục phía trên. Không mở index.html của project bằng cách bấm đúp để thay cho dev server.

App báo thiếu App ID / không có quyền / trang trắng

Kiểm tra .env.local nằm đúng chỗ, hai tên biến đúng chính tả và đã thay placeholder. Dừng / chạy lại server sau khi sửa env. Nếu chưa có quyền app, nhờ team cấp đúng tài khoản; không tắt auth trong code. Để xem lỗi, mở F12 → Console, gửi lỗi đã che thông tin nhạy cảm; không dán token / cookie hoặc toàn bộ response chứa dữ liệu khách hàng vào chat AI.

Commit báo Please tell me who you are

Thực hiện lại bước 6.5 để cài user.name và user.email trong repo. Đó là danh tính commit, không phải mật khẩu. Kiểm tra nhánh son-dev trước khi chạy lại commit.

Push bị non-fast-forward / rejected

Không force push. Xem git status -sb và nhờ team kiểm tra thay đổi remote. Khi repo sạch, có thể dùng quy trình git pull --ff-only origin son-dev; nếu vẫn bị từ chối do nhánh phân kỳ thì dừng và phối hợp xử lý, không tự merge / rebase.

AI đề nghị tạo dữ liệu mẫu trên local để thử Save

Từ chối thao tác đó vì local đang dùng dữ liệu production. Yêu cầu AI dùng fixture / client mock không gọi backend thật hoặc chờ một backend thử nghiệm đã cách ly. “Tạo xong xóa lại” hoặc “dùng một draft” không phải ngoại lệ.

13Checklist trước task đầu tiên

Đối chiếu từng dòng. Có thể in hướng dẫn để đánh dấu; các ô dưới đây là checklist đọc, không ghi dữ liệu vào CRM.

  • git --version chạy được.
  • node -v đạt ≥ 20; máy cài mới ưu tiên Node 22 LTS.
  • npm -v hoặc npm.cmd -v chạy được.
  • Nếu cần NVM: nvm list có Node đã cài và node -v đúng bản đã chọn.
  • Clone đúng HaiRetail/CRM-Base, remote origin đúng repo.
  • git branch --show-current trả về chính xác son-dev.
  • VS Code đang mở thư mục gốc CRM-Base, có package.json.
  • Đã đặt tên / email commit của Sơn, không để email placeholder.
  • .env.local có cấu hình thật do team cấp và đang được Git bỏ qua.
  • npm ci cài xong không có lỗi chặn.
  • Dev server chạy đúng 5178 và mở được trên trình duyệt.
  • Đã được cấp quyền app; chỉ kiểm tra phần xem dữ liệu.
  • Đã đọc AGENTS.md và dán khối luật ở bước 10 cho AI.
  • Hiểu rõ: mọi commit của Sơn ở son-dev; mọi dữ liệu local là production, chỉ được xem.

Khi nhờ hỗ trợ, cung cấp: bước đang làm, lệnh vừa chạy, lỗi đầy đủ đã che thông tin nhạy cảm, phiên bản Node / npm và nhánh hiện tại. Không gửi mật khẩu, access token hay nội dung .env.local vào kênh công khai.
