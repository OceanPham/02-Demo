4. Plan per service

4.1 Hostinger account

  1. One Hostinger account in the company's name, with a company email address (not a personal one) and two-factor login on.
  2. Daniel is the owner; Joost a second admin if wanted. Ocean gets access through Hostinger's account-sharing feature, so no passwords are shared.
  3. Have VPS KVM 2 ready before Day 1: 24-month term, datacenter in Europe, OS "Ubuntu 24.04" (plain, no control panel), as proposed in the original plan. Buying on Black Friday (27 November 2026) remains an option; confirm the price and available plan at purchase. Confirm the "Daily backups" add-on or an equivalent backup arrangement.

4.2 Domains and DNS

The order matters: first copy all DNS records to Hostinger, then move the domain, then switch DNS. This way mail and website keep working the whole time.

  1. Copy every DNS record: export the zone file from Cloudflare (cadinvo.com, cadinvo.nl) and write down every record at Strato (dacu3d.nl). Create the same records in Hostinger DNS. We compare old and new with a script before switching.
  2. Lower the TTL of the records to 5 minutes, one day before the switch, so a mistake can be fixed fast.
  3. Request the transfer codes:
    • dacu3d.nl: transfer code at Strato. Do not cancel the Strato package before the domain has moved: the domain is part of that package and could be deleted with it.
    • cadinvo.nl: transfer code at Hostnet.
    • cadinvo.com: confirm the managing account at Hostnet, remove the transfer lock and request the EPP/auth code; complete the registrar's verification requirements. The original plan allowed 5–7 days and a one-year extension; confirm processing time and expiry when ordering the transfer.
  4. Start the transfers at Hostinger (.nl transfers are supported; they usually finish within hours). Confirm the approval emails.
  5. Switch the name servers to Hostinger, one domain at a time: dacu3d.nl first (no website, lowest risk), then cadinvo.nl, then cadinvo.com.
  6. After each switch: send and receive a test mail, open the website, check Microsoft 365 admin → Domains shows "healthy".
  7. Redirects that Cloudflare does now (cadinvo.nl and cadinvo.com → www.cadinvo.com) are done by the web server on the VPS, with free SSL certificates.

4.3 Email (recommended: stays on Microsoft 365)

  1. No mailbox moves. We copy the Microsoft records exactly: MX, SPF, DKIM (selector1/2._domainkey), autodiscover, enterpriseregistration, enterpriseenrollment and the MS= verification records.
  2. Add DMARC to all three domains: start in "report only" mode, monitor reports for about two weeks, and move to "quarantine" only after legitimate senders are verified. Monitoring continues during aftercare.
  3. Before cancelling Strato and Hostnet: log in to their webmail; if there are old mails you want to keep, we copy them into Microsoft 365 or export them.
If you still want mail at Hostinger (Hostinger Business Email): every mailbox must be moved, Teams/OneDrive/SharePoint stay at Microsoft anyway, and the CRM features that read and send Outlook mail and use OneDrive would have to be rebuilt. We do not recommend this.

4.4 All websites: codebase on the VPS

  1. Inventory every DaCu3D and Cadinvo website, starting with www.cadinvo.com on systeme.io: pages, assets, contact forms, mailing lists, newsletters, funnels, courses and payments. Export contacts and the list of page addresses.
  2. Confirmed: all websites use a codebase. Rebuild and deploy the websites on the Hostinger VPS. Keep the source in company-controlled Git repositories, with documented build and deployment steps. Shared components can be reused where useful.
  3. Agree the pages, content, design and owner before Day 1 (D2). Content updates go through the codebase; the handover must explain how to request and publish changes.
  4. Map each existing form and other systeme.io feature to its replacement. Include required integrations in the agreed scope and validate them using isolated sample data. Do not cancel a feature that has no working replacement.
  5. Preserve page addresses where possible; otherwise add permanent redirects. Check HTTPS, mobile layouts, metadata, analytics and forms before launch.
  6. systeme.io stays active until the replacement site and all required features are live and approved.
  7. dacu3d.nl: redirect to www.cadinvo.com, or publish its own codebase website/page (D4). cadinvo.nl keeps its redirect unless a separate website is agreed; any separate website also uses a codebase.

4.5 CRM (from Base44)

  1. Follows the separate CRM migration plan. New address, for example crm.cadinvo.com, created in Hostinger DNS. Moving from Base44 includes replacing backend services, not just deploying the React frontend; the migration must be ready for rehearsal before this two-week rollout starts.
  2. Use KVM 2 for preparation in an environment isolated from production; promote it only after acceptance checks. If more resources are needed later, upgrade according to the provider's available options.
  3. Files (chat attachments, images, documents) on the VPS disk. The original plan estimated 3–6 GB of data and a 100 GB disk; confirm capacity before migration.
  4. Backups: database and files every night, encrypted, to a dedicated Microsoft 365 SharePoint/OneDrive folder (off-site, no new provider), plus Hostinger daily backups. We test a restore before go-live.
  5. Schedule cutover near the end of Week 2, after DNS and website checks pass, in a separate change window. If the Christmas–New Year preference is retained, choose Day 1 so the final cutover falls in that window. Keep Base44 available read-only for at least 2 weeks after cutover; agree and rehearse data reconciliation before any rollback.

4.6 WhatsApp server and n8n

If these run on a separate server or a paid cloud plan, plan to move them onto the same VPS after checking resources and integrations; cancel the old service only when the replacement works. Please confirm where they run (D7).

Kopen op Black Friday (27 november 2026) blijft een optie; controleer prijs en beschikbaar pakket bij aankoop. Bevestig de optie "Daily backups" of een gelijkwaardige back-upvoorziening.

4.2 Domeinen en DNS

De volgorde is belangrijk: eerst alle DNS-records naar Hostinger kopiëren, dan het domein verhuizen, dan de DNS omzetten. Zo blijven mail en website de hele tijd werken.

  1. Alle DNS-records kopiëren: het zonebestand exporteren uit Cloudflare (cadinvo.com, cadinvo.nl) en elk record bij Strato noteren (dacu3d.nl). Dezelfde records aanmaken in de DNS van Hostinger. Vóór het omzetten vergelijken we oud en nieuw met een script.
  2. De TTL verlagen naar 5 minuten, een dag vóór het omzetten, zodat een fout snel te herstellen is.
  3. De verhuiscodes aanvragen:
    • dacu3d.nl: verhuiscode bij Strato. Zeg het Strato-pakket niet op voordat het domein verhuisd is: het domein hoort bij dat pakket en kan anders mee verwijderd worden.
    • cadinvo.nl: verhuiscode bij Hostnet.
    • cadinvo.com: bevestig het beheeraccount bij Hostnet, verwijder het verhuisslot en vraag de EPP/autorisatiecode aan; voldoe aan de verificatie-eisen van de registrar. Het oorspronkelijke plan rekende op 5–7 dagen en een jaar verlenging; bevestig verwerkingstijd en vervaldatum bij de aanvraag.
  4. De verhuizingen starten bij Hostinger (.nl-verhuizingen worden ondersteund en zijn meestal binnen een paar uur klaar). De bevestigingsmails goedkeuren.
  5. De naamservers naar Hostinger omzetten, één domein tegelijk: eerst dacu3d.nl (geen website, laagste risico), dan cadinvo.nl, dan cadinvo.com.
  6. Na elke omzetting: een testmail versturen en ontvangen, de website openen, en in Microsoft 365-beheer → Domeinen controleren dat alles "in orde" is.
  7. Doorverwijzingen die Cloudflare nu doet (cadinvo.nl en cadinvo.com → www.cadinvo.com) doet straks de webserver op de VPS, met gratis SSL-certificaten.

4.3 E-mail (advies: blijft op Microsoft 365)

  1. Er verhuist geen enkele mailbox. We kopiëren de Microsoft-records precies: MX, SPF, DKIM (selector1/2._domainkey), autodiscover, enterpriseregistration, enterpriseenrollment en de MS=-verificatierecords.
  2. Voeg DMARC toe aan alle drie de domeinen: begin met alleen rapporteren, volg de rapporten ongeveer twee weken en schakel pas naar quarantaine nadat legitieme afzenders zijn gecontroleerd. Deze monitoring loopt door tijdens de nazorg.
  3. Vóór het opzeggen van Strato en Hostnet: inloggen op hun webmail; staan er oude mails die jullie willen bewaren, dan kopiëren we die naar Microsoft 365 of exporteren we ze.
Als jullie toch mail bij Hostinger willen (Hostinger Business Email): elke mailbox moet verhuizen, Teams/OneDrive/SharePoint blijven toch bij Microsoft, en de CRM-functies die Outlook-mail lezen en versturen en OneDrive gebruiken moeten opnieuw gebouwd worden. Dat raden we niet aan.

  3. Spreek vóór dag 1 pagina's, inhoud, ontwerp en verantwoordelijke af (D2). Inhoudswijzigingen lopen via de codebase; de overdracht legt uit hoe wijzigingen worden aangevraagd en gepubliceerd.
  4. Koppel elk bestaand formulier en elke andere systeme.io-functie aan een vervanger. Neem benodigde integraties op in de afgesproken scope en controleer ze met geïsoleerde voorbeelddata. Zeg geen functie op zonder werkende vervanger.

4.2 Tên miền và DNS

Thứ tự: sao chép đầy đủ bản ghi DNS sang Hostinger, chuyển tên miền, sau đó đổi DNS. Giữ cấu hình cũ hoạt động cho đến khi cấu hình mới đã được kiểm tra.

  1. Sao chép mọi bản ghi DNS: xuất zone từ Cloudflare (cadinvo.com, cadinvo.nl) và ghi lại tất cả bản ghi tại Strato (dacu3d.nl). Tạo cấu hình tương ứng tại Hostinger và dùng script đối chiếu trước khi đổi.
  2. Hạ TTL xuống 5 phút trước thời điểm đổi một ngày, để dễ xử lý khi cần sửa bản ghi.
  3. Lấy mã chuyển tên miền:
    • dacu3d.nl: lấy mã tại Strato. Không hủy gói Strato trước khi tên miền chuyển xong; tên miền nằm trong gói và có thể bị xóa cùng gói.
    • cadinvo.nl: lấy mã tại Hostnet.
    • cadinvo.com: kiểm tra tài khoản quản lý tại Hostnet, gỡ khóa chuyển và lấy mã EPP/auth; thực hiện yêu cầu xác minh của nhà đăng ký. Bản gốc dự trù 5–7 ngày cho chuyển .com và cộng thêm một năm; xác nhận thời gian và ngày hết hạn khi đặt chuyển.
  4. Bắt đầu chuyển tại Hostinger và duyệt email xác nhận. Theo bản gốc, .nl được hỗ trợ và thường xử lý trong vài giờ; thời gian thực tế phụ thuộc nhà đăng ký.
  5. Đổi nameserver từng tên miền: dacu3d.nl trước, rồi cadinvo.nl, cuối cùng cadinvo.com.
  6. Sau mỗi lần đổi: kiểm tra gửi/nhận email, website và trạng thái tên miền trong Microsoft 365 admin → Domains.
  7. Chuyển hướng từ cadinvo.nl và cadinvo.com tới www.cadinvo.com sẽ do web server trên VPS xử lý, kèm chứng chỉ SSL.

4.3 Email — đề xuất giữ Microsoft 365

  1. Không di chuyển hộp thư. Sao chép chính xác các bản ghi Microsoft: MX, SPF, DKIM (selector1/2._domainkey), autodiscover, enterpriseregistration, enterpriseenrollment và xác minh MS=.
  2. Bổ sung DMARC cho cả ba tên miền: bắt đầu ở chế độ chỉ báo cáo, theo dõi báo cáo khoảng hai tuần; chỉ tăng lên quarantine sau khi xác nhận các nguồn gửi hợp lệ. Theo dõi này thuộc giai đoạn chăm sóc sau chuyển.
  3. Trước khi hủy Strato/Hostnet: kiểm tra webmail cũ; nếu có email cần giữ thì chuyển vào Microsoft 365 hoặc xuất lưu trữ.
Nếu vẫn muốn chuyển email sang Hostinger Business Email: phải di chuyển từng hộp thư, trong khi Teams/OneDrive/SharePoint vẫn cần Microsoft và các tích hợp CRM liên quan phải điều chỉnh. Không đề xuất hướng này.

4.4 Mọi website dùng codebase trên VPS

  2. Đã chốt: mọi website dùng codebase. Xây lại và triển khai trên Hostinger VPS. Mã nguồn nằm trong Git repository do doanh nghiệp quản lý, có hướng dẫn build/deploy; tái sử dụng component chung khi phù hợp.
  3. Chốt danh sách trang, nội dung, thiết kế và người phụ trách trước Ngày 1 (D2). Cập nhật nội dung qua codebase; bàn giao hướng dẫn yêu cầu thay đổi và xuất bản.
  4. Đối chiếu từng form và tính năng systeme.io với chức năng thay thế. Đưa tích hợp cần thiết vào phạm vi đã duyệt, kiểm tra bằng dữ liệu mẫu cách ly. Không hủy tính năng chưa có bản thay thế hoạt động.

4.5 CRM — chuyển từ Base44

  1. Theo plan migration CRM riêng. Tạo địa chỉ mới, ví dụ crm.cadinvo.com, trong DNS Hostinger. Chuyển khỏi Base44 cần thay thế cả backend, không chỉ deploy React frontend; bản migration phải sẵn sàng để chạy thử trước khi bắt đầu đợt triển khai hai tuần.
  2. Dùng KVM 2 làm môi trường chuẩn bị, tách biệt với production; chuyển sang vận hành chính thức sau khi kiểm tra đạt yêu cầu. Nếu cần thêm tài nguyên sau này thì nâng cấu hình theo khả năng của nhà cung cấp.
  3. Tệp đính kèm, ảnh và tài liệu lưu trên đĩa VPS. Bản gốc ước lượng dữ liệu 3–6 GB, đĩa 100 GB; xác nhận lại dung lượng trước khi chuyển.
  4. Sao lưu database và tệp mỗi đêm, mã hóa, lưu thêm vào thư mục SharePoint/OneDrive dành riêng trên Microsoft 365, kết hợp sao lưu Hostinger đã thống nhất. Kiểm tra khôi phục trước khi lên live.
  5. Chuyển CRM gần cuối Tuần 2, sau khi DNS và website ổn định, trong khung thay đổi riêng. Nếu giữ mong muốn chuyển dịp Giáng sinh–Năm mới thì chọn Ngày 1 phù hợp. Giữ Base44 chỉ đọc ít nhất hai tuần; thống nhất và diễn tập đối soát dữ liệu trước khi quay lại hệ thống cũ.
